Why Tables Are Appropriate Here

A timetable is inherently tabular, grid-based data: every entry is defined by the intersection of two variables — a day and a period — exactly what an HTML <table> is built to represent. Using <table> instead of <div> grids or CSS layout gives several concrete benefits:

  • Semantic correctness: screen readers and assistive tools announce table headers (<th>) and can read "Monday, Period 3, DBMS" as a related unit, which a purely visual div-grid cannot convey without extra ARIA work.
  • Natural handling of merged cells: a lunch break or a two-hour lab session spans several periods or days. rowspan and colspan express this directly, whereas replicating it with CSS grid needs manual column/row-span calculations.
  • Row/column scoping: scope="row" and scope="col" let each data cell be unambiguously tied to its day and period for both sighted and non-sighted users.
  • Predictable alignment: tables auto-align columns of unequal content length, keeping the grid readable without manual width calculations.
